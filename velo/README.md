# Велокарта

Карта для велосипедиста в стиле навигаторов: схема и спутник, тёмная тема, перепады высот, маршруты по велодорогам с оценкой сложности, пошаговая навигация, запись поездок и лобби с гонками и погонями. Курсоры игроков — 128 странных моделей в стиле line art.

Два варианта: **веб-приложение** (PWA, открывается в браузере и ставится на экран «Домой») и **Android-приложение (APK)** — та же веб-версия, упакованная Capacitor.

## Что умеет

| Вкладка / кнопка | Что делает |
|---|---|
| **Карта** | Ваша позиция, скорость, заряд. Кнопки справа: следовать за мной, слой (схема/спутник), перепады высот, тёмная тема. Курсоры игроков из лобби со скоростью и направлением. |
| **Поиск «Куда едем?»** | Адрес ищется в OpenStreetMap (Nominatim); выбранное место становится точкой назначения, маршрут строится от вашей позиции. |
| **Маршрут** | Точки ставятся нажатием на карту. Маршрут строится по велодорогам (BRouter), показывает длину, время, подъём, **сложность** (лёгкий → экстрим) и **профиль высот**. «Поехать» запускает навигацию. |
| **Навигация** | Карточка следующего поворота с расстоянием («Направо через 318 м»), остаток пути и время прибытия. Сошли с маршрута — перестраивается автоматически. |
| **Поездки** | Записанные поездки: длина, время, средняя и максимальная скорость. Показ на карте, GPX, удаление. |
| **Офлайн** | Загрузка карт области: схема или спутник, выбранный зум. Пакеты «Москва и область», «Санкт-Петербург и область», «Вся Россия (обзор)» или текущий вид. |
| **Лобби** | Код на 6 символов, вход по коду, список игроков (скорость, заряд, расстояние, курсор). «Мой курсор» — выбор из 128 моделей. |

### Гонка и повтор финиша

Хост выбирает маршрут и запускает отсчёт 10 секунд. Первый, кто доехал до финиша, получает 1 место; остальным даётся окно ожидания (по умолчанию 2 минуты, настраивается). Когда заезд закрыт, **все курсоры проигрываются по своим траекториям**: каждый проезжает путь, оставляя цветную линию, затем заезжают на парковку вокруг флажка финиша. После этого показываются итоги с местами и временами. Кнопка «Пропустить» сразу показывает итог.

### Погоня

Хост отмечает догоняющих; остальные — беглецы. Догоняющий побеждает, если подъехал к беглецу ближе **2 м** и держит это **2 секунды** подряд. Время вышло — побеждают беглецы.


## Маршруты с максимумом велодорожек

Режим «Велодорожки без потери времени» (по умолчанию) строит параллельно несколько вариантов BRouter (`safety`, `trekking`, `fastbike` и альтернативу `trekking`), считает для каждого долю длины по велоинфраструктуре (велодорожки, велополосы, обозначенные велотропы, веломаршруты) и выбирает вариант с наибольшей долей, если он не «дороже» самого выгодного (допуск 0%): из самых выгодных вариантов берётся тот, где больше велодорожек. «Стоимость» — длина плюс 8 м за каждый метр подъёма: время у разных профилей BRouter считается с разными скоростями, поэтому напрямую его сравнивать нельзя. В сводке маршрута видно долю велодорожек и сколько минут добавил выбор («без потери времени»). На карте участки по велодорожкам — зелёные.

Проверка на живых маршрутах по Москве (BRouter, ноябрь 2026):

| Маршрут | Быстрый (`fastbike`) | Выбранный | Цена |
|---|---|---|---|
| Сокольники → Измайлово | 7,38 км, велодорожки 15% | 7,00 км, 38% | без потери (вариант ещё и короче) |
| Красная пл. → ВДНХ | 9,34 км, 3% | 9,34 км, 3% (быстрый) | вариант с 42% велодорожек дороже на 5,8% — не берётся |
| Мосфильмовская → Парк Горького | 10,76 км, 0% | 10,30 км, 43% | без потери (вариант с 84% длиннее на 156 м — не берётся) |

Логика выбора — `js/routing.js`, тесты — `server/test/routing.test.js`. Допуск задаётся в `pickBest()` (сейчас 0%).

Слой «Велодорожки» (кнопка слоёв на карте) — CyclOSM поверх чёрной схемы: велодорожки и велополосы выделены зелёным.

Поиск с подсказками: при нажатии на поле сразу видны «Мои места» и «Недавние», при вводе — подсказки адресов рядом с вами (Photon от komoot на данных OSM; публичный Nominatim запрещает поиск «по мере ввода»). Одинаковые отрезки улиц склеиваются, у каждой подсказки — адрес и расстояние.

Мои места: долгое нажатие на карту открывает меню «Маршрут сюда / Сохранить». Сохранённые точки видны на карте белыми метками с подписью, есть в подсказках поиска и во вкладке «Маршрут» (маршрут, показ на карте, удаление). Хранятся на телефоне (IndexedDB), кнопка «В мои места» сохраняет текущую точку назначения.

## Структура

```
velo/
  index.html, style.css, manifest.webmanifest              — веб-приложение
  vendor/leaflet.js|css                                  — Leaflet 1.9.4 (без CDN)
  js/geo.js        — расстояния, проекция на маршрут, повороты по геометрии (общая для клиента и сервера)
  js/vectorstyle.js — векторный чёрный стиль карты (MapLibre, OpenFreeMap)
  js/routing.js    — разбор ответа BRouter, доля велодорожек, выбор варианта
  js/elevation.js  — тайлы высот, профиль, сложность, слой «перепады высот» с тенями
  js/icons.js      — иконки в стиле line art (вместо эмодзи)
  js/skins.js      — 128 курсоров игроков
  js/store.js      — IndexedDB (поездки, маршруты, пакеты) и настройки
  js/net.js        — клиент лобби через сервер (WebSocket) и переключатель режимов
  js/net-p2p.js    — лобби без сервера: прямая связь, переход прав хоста
  js/mesh.js       — WebRTC между телефонами, знакомство через трекеры WebTorrent
  js/roomhost.js   — комната лобби на телефоне хоста
  js/game.js       — правила лобби, гонки и погони (общие для сервера и телефона)
  js/legal.js      — соглашение, защита местоположения, экран согласия, удаление данных
  js/app.js        — карта, GPS, навигация, маршруты, поиск, записи, вкладки
  js/lobby.js      — лобби, гонка, погоня, курсоры и повтор финиша
  server/          — сервер лобби (Node.js + ws): раздаёт папку velo/ и WebSocket /ws
    server.js      — HTTP и WebSocket
    test/          — npm test
  app/             — Android-приложение (Capacitor): упаковывает веб-версию в APK
```

## Веб-версия: запуск

```bash
cd velo/server
npm install
npm start            # http://localhost:8080
```

Для GPS и service worker нужен HTTPS, поэтому сервер лучше задеплоить (Render, Fly.io, VPS с nginx). Адрес лобби подставится сам, если страница открыта с того же адреса, что и сервер. Приложение можно публиковать отдельно (например, на GitHub Pages из папки `velo/`) — тогда в поле «Сервер лобби» введите `wss://ваш-сервер/ws`.

Тесты правил:

```bash
cd velo/server && npm test
```


## Лобби без сервера (до 10 игроков)

По умолчанию лобби работает без своего сервера: телефоны связываются напрямую (WebRTC), а правила гонки и погони считает телефон хоста.

- **Знакомство.** Чтобы телефоны нашли друг друга, используются открытые трекеры WebTorrent (`tracker.openwebtorrent.com`, `tracker.webtorrent.dev`). Через них идут только предложения соединения, зашифрованные ключом из кода лобби (AES-GCM), — трекер не видит ни позиций, ни сетевых адресов. Позиции и сообщения идут напрямую между телефонами.
- **Хост.** Создатель лобби — хост: его телефон держит комнату (`js/roomhost.js`) по тем же правилам, что и сервер (`js/game.js`). До 10 игроков.
- **Если хост ушёл или пропала связь,** через ~3 секунды права переходят игроку на связи с наименьшим id: его телефон поднимает комнату из последнего состояния (игроки, маршрут, идущая гонка), остальные переподключаются к нему сами.
- **Вход по коду** обычно занимает 5–20 секунд (поиск через трекер и установка соединения).

Ограничения:
- у части мобильных операторов прямое соединение между двумя телефонами может не установиться (жёсткий NAT); тогда нужен ретранслятор (TURN-сервер) — его можно добавить в `iceServers` в `js/mesh.js`;
- если хост выключит телефон и никто не останется на связи, лобби пропадёт;
- открытые трекеры бесплатны, но без гарантий доступности.

Свой сервер не обязателен: если указать его адрес (`js/config.js` → `serverUrl` или поле «Сервер» в лобби), лобби пойдёт через сервер, как раньше (до 30 игроков).

Модули: `js/mesh.js` — прямая связь и знакомство через трекеры; `js/roomhost.js` — комната на телефоне хоста; `js/net-p2p.js` — лобби без сервера с переходом прав хоста; `js/game.js` — общие правила (сервер берёт их же).

## Развёртывание сервера лобби (не обязательно)

Сервер и веб-версия собираются в один Docker-образ (`velo/Dockerfile`):

```bash
docker build -t velokarta ./velo
docker run -d -p 8080:8080 --restart unless-stopped velokarta
```

Что умеет сервер:
- `GET /healthz` — проверка живости для хостинга (`{"ok":true,"rooms":…,"connections":…}`); в Docker-образе настроен `HEALTHCHECK`;
- лимиты: не больше 5000 лобби (`MAX_ROOMS`) и 20 соединений с одного IP (`MAX_CONN_PER_IP`), 20 сообщений в секунду на соединение;
- переподключение: телефон сменил сеть — возвращается в лобби по токену, старое соединение закрывается, игрок не помечается «не в сети»;
- хост без связи дольше 30 секунд — права хоста переходят игроку на связи;
- после перезапуска сервера лобби (они в памяти) пропадают; приложение само возвращает игроков на экран создания лобби с сообщением;
- корректная остановка по `SIGTERM`.

Ссылка-приглашение: «Поделиться» в лобби отправляет код и ссылку `…/?join=КОД`, по ней код подставляется сам. Для ссылок из APK впишите адрес веб-версии в `js/config.js` (`webUrl`).

Тесты сервера (настоящий сервер и WebSocket-клиенты): `cd velo/server && npm test`.

Нужен HTTPS (для GPS в браузере и `wss://`): его даёт хостинг или обратный прокси (nginx, Caddy). Для ФЗ-152 выбирайте хостинг в России (например, любой VPS или облако с Docker в РФ). После развёртывания впишите адрес в `js/config.js` и пересоберите APK.

## Android-приложение (APK)

Нужны JDK 17+, Android SDK (platform 35, build-tools 35), Node.js 18+.

```bash
cd velo/app
npm install
npm run apk:debug    # → android/app/build/outputs/apk/debug/app-debug.apk
```

`npm run sync` копирует веб-версию в `www/` и обновляет Android-проект; изменения в `velo/` попадают в APK после этой команды.

Адрес сервера лобби задаётся в `js/config.js` (`serverUrl: 'wss://ваш-домен/ws'`) — тогда APK и веб-версия подключаются сами. Если поле пустое, адрес вводится на вкладке «Лобби» → «Сервер». Для публикации нужна подпись релизной сборкой (`npm run apk:release` + собственный ключ); ключ создаётся один раз и хранится у вас — в репозиторий он не попадает.

## Как устроено

- **Схема и спутник.** Схема — векторная (MapLibre GL на тайлах OpenFreeMap, схема OpenMapTiles, данные OSM): рисуется под плотность экрана, поэтому линии и подписи чёткие, как в Яндекс Картах. Стиль свой (`js/vectorstyle.js`): чёрный фон, белые магистрали, серые улицы, пунктирные тропы, серая вода, зелёные велодорожки. Если на устройстве нет WebGL, включается растровая схема OSM. Спутник — Esri World Imagery. Высоты — открытые Terrain Tiles (формат terrarium).
- **Тема.** Единая чёрная: интерфейс и карта. Схема OSM инвертирована в тёмную, дороги светлые; своя позиция — простая стрелка.
- **Сложность маршрута.** Высоты берутся каждые 50 м вдоль маршрута, сглаживаются скользящим средним. Сложность — подъём на километр, с повышением уровня, если самый крутой участок (≈100 м) круче 12%.
- **Повороты.** Определяются по форме маршрута: отклонение направления на ±25 м от каждой точки; резкие изгибы ≥35° считаются поворотами. Названий улиц нет.
- **Курсоры.** Каждый игрок выбирает модель; она поворачивается по направлению движения и видна всем в лобби.
- **Повтор финиша.** Сервер записывает траекторию каждого участника раз в 2 секунды и отправляет повтор всем после окончания гонки.

## Ограничения

- **Точность GPS.** Телефонный GPS обычно даёт 3–10 м. Порог 2 м в погоне на практике почти недостижим; сервер не засчитывает контакт, если погрешность любого из игроков больше `maxAccM` (по умолчанию 15 м).
- **Навигация — не Яндекс.** Повороты вычисляются по геометрии маршрута, без голосовых подсказок и без учёта полос и знаков. Для настоящей пошаговой навигации нужен маршрутизатор с инструкциями.
- **Тайлы OSM.** Политика OpenStreetMap ограничивает нагрузку на серверы; приложение загружает тайлы только для отображения.
- **Спутник Esri.** Условия использования Esri разрешают показ с указанием авторства.
- **Маршруты** строятся онлайн через публичный BRouter. Офлайн-маршрутизации в браузере нет.
- **iPhone.** Safari приостанавливает страницу при блокировке экрана — запись и трансляция позиций могут прерываться. Battery API на iPhone недоступен, заряд показывается как «—».
- **Фон на Android.** Во время записи поездки, навигации и в лобби APK включает фоновую службу геолокации (плагин `@capacitor-community/background-geolocation`) с уведомлением «Велокарта», поэтому позиция идёт и при выключенном экране. Вне этих режимов используется обычный GPS. На телефоне поведение нужно проверить: некоторые прошивки (Xiaomi, Huawei) закрывают фоновые службы — помогает исключение приложения из экономии батареи.
- **Не проверено на устройствах.** Проверено в headless-браузере с подменой GPS и в сборке APK; на реальных телефонах GPS, вибрация и поведение WebView нужно проверить.

## Соглашение и защита местоположения

При первом запуске пользователь видит экран согласия: соглашение и политика защиты местоположения открываются по ссылкам. GPS, лобби и запись поездок включаются только после согласия. Тексты в `js/legal.js` — **черновик**: перед публикацией их должен проверить юрист, а вместо `[в квадратных скобках]` подставить реквизиты оператора.

Что обеспечено в коде:
- позиция передаётся только участникам лобби; сервер хранит её в памяти и не пишет в журналы и на диск;
- последний участник вышел — лобби удаляется сразу; потерявший связь исключается через 2 минуты;
- поездки и маршруты остаются на устройстве, GPX выгружается только по команде пользователя;
- кнопка «Удалить мои данные» (вкладка «Лобби») стирает настройки, поездки, маршруты и согласие на устройстве.

Для ФЗ-152 хранение данных граждан РФ должно быть в России: при развёртывании сервера лобби выберите хостинг в РФ и укажите место хранения в политике.
